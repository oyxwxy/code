# Drawer

NovelAI 프롬프트를 **공개 / 비밀번호 / 비공개**로 백업하고, 링크로 공유하는 블로그형 사이트예요.
빌드 도구 없이 파일만 올리면 동작하는 순수 HTML + JS(ES Modules) + Firebase(Auth, Firestore) + ImgBB(이미지) 구성입니다.

## 기능

- **글 종류 3가지**
  - **그림체**: 그림체 프롬프트 + 네거티브 + 생성 설정(모델·Effort·샘플러·Steps·Guidance·Seed·크기 등) — 부정/설정은 그림체에만 있어요
  - **캐릭터**: 기본 캐릭터 프롬프트 + 변형 여러 개(＋ 버튼으로 사복·교복·수영복 등). 변형마다 따로 복사, "기본과 함께" 복사도 가능
  - **배포 프롬**: 그림체·캐릭터를 뺀 상황/꾸밈 프롬프트
  - 블로그에서 종류별로 걸러 볼 수 있어요
  - **스포일러 가리기**: 공개 글의 썸네일·내용을 흐리게 가리고, 눌러야 보이게 할 수 있어요 (화면에서 가리는 기능이라 보안용은 아니에요)
  - **이미지별 스포일러 가리기**: 글쓰기에서 이미지에 마우스를 올리면 나오는 눈 버튼으로 이미지마다 가릴 수 있어요. 보기 화면·크게 보기에서 흐리게 가려지고 눌러야 보여요. 대표 이미지를 가리면 목록 썸네일도 흐려져요 (화면용이라 보안은 아니에요)
  - **변형(추가 프롬프트)별 스포일러 가리기**: 캐릭터 글의 변형마다 '스포일러 가리기'를 켜면 그 프롬프트만 흐리게 가려지고, 눌러야 보여요 (화면용이라 보안은 아니에요)
  - **작성일 지정**: 글쓰기에서 작성일을 원하는 날짜로 바꿀 수 있어요. 블로그의 글 순서는 날짜와 별개로 끌어서 정하고, '작성일 최신순으로 정리' 버튼으로 날짜순으로 되돌릴 수 있어요
  - **끌어서 순서 바꾸기**: 내 블로그의 글, 글쓰기의 태그·캐릭터 변형·이미지를 손잡이(⋮⋮)를 끌어 옮겨요 (마우스·터치 모두)
  - **꾸미기 → 글 종류 이름 · 공개**에서 종류 이름을 바꾸고, 다른 사람에게 보일지 숨길지 정할 수 있어요 (숨겨도 내 블로그에서는 보여요)
- **게시판**: 설정 → 게시판에서 만들고 순서를 바꿔요. 글쓰기에서 게시판을 고르고, 블로그 위쪽 탭으로 모아 봐요. 이미 있는 글은 블로그의 '게시판으로 옮기기'로 여러 개를 한 번에 옮겨요. 글이 없는 게시판은 다른 사람에게 안 보여요 (게시판 정보는 프로필 theme 안에 저장돼서 Firestore 규칙은 그대로예요)
- **게시판 전체 글 개수 · 태그 더보기**: 사이드의 '게시판' 제목 옆에 전체 글 개수가 나와요. 태그는 처음 10개만 보이고 '더보기'로 펼치고 접어요(골라 둔 태그는 접혀도 보여요)
- **목록 썸네일 꽉 채우기**: 가로로 긴 그림은 위아래 여백을 두고 전체를 보여주는 게 기본이에요. 글쓰기 → 이미지에서 '목록 썸네일 꽉 채우기'를 켜면 그 글만 여백 없이 칸을 가득 채워요(`posts`의 `thumbFill`, 규칙 변경 없음)
- **대문 배너 슬라이드** (테스트 중: `config.js` 의 `BANNER_SLIDE_FOR_ALL = false` 라서 관리자·`BETA_HANDLES` 에게만 보여요. `true` 로 바꾸면 전체 공개): 꾸미기 → 블로그 머리말을 '대문 배너'로 두면 '슬라이드 사진 추가'가 나와요. 대문 배너 사진이 1번이고 추가 사진(최대 5장, 6 : 1로 자름)이 이어서 3·5·8·12초 간격으로 서서히 바뀌며 자동으로 넘어가요. 마우스를 올리면 멈추고, 그때 배너 아래쪽에 작은 점이 나타나서 직접 넘길 수도 있어요(평소엔 투명, 터치 화면은 은은하게 항상 보여요). 보는 사람이 관리자일 때만 넘어가고, 다른 사람에게는 대문 배너 한 장만 보여요(`theme.bannerMore`, `theme.bannerSec` — Firestore 규칙은 그대로예요)
- **디데이 창**: 블로그 이름 옆 알약을 누르면 파스텔 색 카드 목록이 열려요. 카드마다 이모지 동그라미, 이름, 큰 D+N / D-N 숫자, 날짜가 보이고 D-DAY 당일은 테두리가 강조돼요
- **디데이 카드 색 · 커플 날짜 계산**: 설정 → 디데이에서 카드마다 색을 정할 수 있어요('자동' / 기본 파스텔 7가지 / 직접 고르기, `ddays[].color`). 커플은 만난 날을 1일로 세요(만난 날 D+1, 100일은 만난 날 +99일째)
- **아이디 바꾸기 (계정당 1번)**: 설정 → 프로필의 '아이디 바꾸기'. 새 아이디가 비어 있어야 하고, 한 번 바꾸면 다시 못 바꿔요(`profiles.handleChanged`, 규칙에서도 막아요). 이전 아이디는 `handles/{이전}.movedTo`로 남겨서 다른 사람이 쓰지 못하고, 이전 블로그 주소로 들어와도 새 주소로 이어져요. 이메일 없이 가입한 계정은 로그인 주소가 '이전아이디@도메인'이라 그대로 두고 새 아이디 문서에 `loginEmail`로 적어 두어서, 다음부터 새 아이디로 로그인해요(이전 아이디로 로그인하면 새 아이디를 알려줘요). 이메일로 가입했거나 이메일을 등록한 계정은 로그인 방법이 그대로예요. `config.js`의 `BETA_HANDLES`에 적은 아이디를 바꾸면 베타 기능이 꺼지니 같이 고쳐 주세요
- **이미지 붙여넣기**: 글쓰기 화면에서 복사한 이미지(스크린샷, 웹의 '이미지 복사', 탐색기에서 복사한 파일)를 Ctrl+V(맥은 ⌘V)로 바로 넣어요. 여러 장도 돼요. 글자만 복사했을 땐 평소처럼 붙여넣어지고, 팝업(자르기 등)이 열려 있을 땐 반응하지 않아요
- **배포 프롬에도 변형**: 글 종류가 '배포 프롬'(`scene`)인 글에서도 캐릭터처럼 '변형'을 여러 개 만들 수 있어요(예: 낮 / 밤 / 비 오는 날). 변형마다 따로 복사하거나 기본 프롬프트와 함께 복사할 수 있고, 변형별 스포일러 가리기도 돼요. 글 종류를 바꿔도 입력한 변형은 유지돼요(그림체로 저장하면 변형은 저장되지 않아요). 저장 구조는 캐릭터와 같아서(`content.variants`) 규칙·백업 변경은 없어요
- **보던 게시판으로 글쓰기**: 내 블로그에서 특정 게시판을 보고 있을 때 '새 글'(블로그 안)이나 맨 위 '글쓰기'를 누르면 글쓰기 화면의 게시판이 그 게시판으로 미리 골라져요(`#/new?board=게시판id`, 바꿀 수 있어요). '전체'·'미분류'를 보고 있거나 다른 화면에서 누르면 지금처럼 미분류예요. 기존 글 수정은 원래 게시판 그대로예요
- **개인 파비콘**: 설정 → 프로필에서 이미지(정사각형으로 잘라 올림) 또는 글자·이모지+배경색으로 만들어요. 내 블로그와 내 글을 보는 사람에게는 내 파비콘이 보여요
- **이미지 보기 통일**: 세로 이미지는 2장씩, 가로 이미지는 잘라내지 않고 전체, 화면이 둘 이상이면 좌우 넘김 버튼(스와이프·방향키 가능). 목록 썸네일도 가로 그림은 전체가 보여요
- **직접 만든 위젯**: 색 선택기, 달력, 드롭다운, 추천 목록 입력, 숫자 입력, 체크박스 (`widgets.js`)
- **NovelAI V5 대응**: 모델 목록에 V5 Full/Curated, 생성 설정에 **Effort(Medium/High)** 추가 (Effort는 V5 Full 전용)
- **공개 범위 3종**: 공개 · 비밀번호(브라우저에서 AES-GCM 암호화) · 비공개(나만). 링크 전용(목록 숨김)도 가능
- **배너** (전체 공개. `config.js` 의 `NEIGHBORS_FOR_ALL = false` 로 바꾸면 관리자·`BETA_HANDLES` 에게만 보여요): 꾸미기 → 이웃 배너에서 작은 배너(4:1)를 만들면, 내 블로그 태그 아래에 내 배너와 그 밑으로 내 이웃 배너들이 떠요. 다른 사람이 내 배너를 누르면 바로 자기 이웃으로 가져가고(다시 누르면 빼기), 마우스를 올리면 블로그 이름·핸들이 보여요. 설정 탭 줄 맨 오른쪽 🔔 에서 누가 내 배너를 가져갔는지 확인해요. 블로그 맨 위 큰 이미지는 '대문 배너'예요
- **디데이** (전체 공개. `config.js` 의 `DDAY_FOR_ALL = false` 로 바꾸면 관리자·`BETA_HANDLES` 에게만 보여요): 설정 → 프로필 → 디데이에서 커플(만난 날부터 D+일수, 100일·주년 계산)과 일반 디데이를 12개까지 만들어요. 블로그 이름 오른쪽에 가장 가까운 기념일이 알약으로 나오고, 누르면 전체 목록이 열려요
- **이미지 자르기 편집기**: 대문 배너(6:1)와 배너(4:1)는 올릴 때 직접 만든 편집기가 떠요. 끌어서 위치, 슬라이더·마우스 휠·두 손가락으로 크기를 맞추고 '적용'하면 그 영역만 저장돼요 (`crop.js`). 글 이미지에도 선택으로 쓸 수 있어요: 글쓰기에서 이미지에 마우스를 올리면 나오는 ✂ 버튼 → 비율 프리셋(자유·원본·1:1·4:3·3:4·3:2·2:3·16:9·9:16·4:5)을 고르고 영역을 정해요
- **초대 코드**: **관리자만** 만들 수 있어요(사용 횟수를 정해 여러 개). 일반 회원에게는 초대 탭이 보이지 않고, 규칙에서도 막혀 있어요
- **이미지 업로드**: 올리기 전에 **메타데이터를 전부 제거**하고(프롬프트 PNG 정보, EXIF, NovelAI 알파채널 숨은 정보) **ImgBB**에 저장해요. 글당 12장, 대표 이미지·순서 변경, 라이트박스
- **비밀번호 찾기**: 가입할 때 이메일을 적으면(선택) 로그인 화면의 '비밀번호를 잊으셨나요?'로 재설정 메일을 받을 수 있어요. 이메일 없이 가입한 계정은 설정 → 프로필 → '로그인 · 복구'에서 나중에 등록할 수 있고, 비밀번호 변경도 거기서 해요
- **내 블로그 미리보기**: 꾸미기 탭의 '미리보기' 버튼(스킨 칸에도 있어요)을 누르면, 저장하지 않은 꾸미기 그대로 내 블로그가 창 안에 떠요. 창 안에서 글을 눌러 프롬창까지 볼 수 있고, PC/모바일 크기를 바꿔 볼 수 있어요. 창 안의 화면이 부모 창의 `window.__drawerPreview` 를 읽는 방식이라(같은 사이트 iframe) 저장되는 건 없어요
- **배경음악 (유튜브)**: 설정 맨 위 오른쪽 ♪ 버튼(알림 옆)에서 유튜브 링크를 최대 20곡까지 넣어요. 섞어 듣기 · 들어오면 바로 재생 시도 · 처음 볼륨을 정할 수 있어요 (`theme.bgm`). 내 블로그와 글 화면 왼쪽 아래에 작은 원판이 뜨고, 누르면 재생/일시정지 · 다음 곡 · 재생 바 · 볼륨이 펼쳐져요. 같은 블로그 안에서는 화면을 옮겨도 이어지고, 다른 곳으로 가면 멈춰요. 유튜브 플레이어는 처음 재생할 때 불러오고(`bgm.js`), 퍼가기가 막힌 영상은 건너뛰어요. 스킨을 쓰면 플레이어 모양도 스킨에 맞춰 바뀌어요
- **전체 게시판 보이기/숨기기**: 설정 → 게시판에서 ‘전체’를 끄면 블로그 왼쪽 목록에서 빠지고, 블로그에 들어오면 보이는 첫 게시판이 먼저 열려요 (`theme.showAll`)
- **스킨** (테스트 중: `config.js` 의 `SKINS_FOR_ALL = false` 라서 관리자·`BETA_HANDLES` 가 볼 때만 적용돼요. 다른 사람에게는 기본 모습 그대로): 설정의 **스킨 탭**(관리자에게만 보임, 꾸미기와 따로 저장)에서 세 가지를 따로 골라요. 스킨마다 **글꼴**(제목 · 꾸밈 · 본문)도 따로 고를 수 있어요 (`theme.skinFonts`). **페이지 스킨**(홈페이지 / 터미널 / 픽셀 아케이드(타이틀 메뉴에 보일 게시판 최대 4개 선택, `theme.gameBoards`) / 그리드 타이틀 — 디데이와 창 모양도 스킨에 맞춰 바뀜), **프롬 모음**(글 목록: 레코드 진열(◀ ▶ 넘기기 버튼 · 끌기 · 휠) / 서랍 / 폴더 인덱스 — 폴더는 눌러서 파일을 열고, 파일을 누르면 프롬이 떠서 복사), **프롬창**(글 보기: 유영 / 신분증 / 여권, '기본 보기'로 원래 화면 전환), **색상 프리셋**(스킨마다 4가지, `theme.skinTone`. 프롬창은 페이지 스킨의 색을 따라가고, 페이지 스킨이 없으면 프롬창 자체 프리셋을 써요. 색 값은 `skins.js` 의 `TONES` 에 모여 있어요). `skins.js` · `skins.css` 에 모여 있고, 기존 화면 구조는 그대로 두고 겉모양만 덧입혀요. 프롬 모음 스킨에서는 끌어서 순서 바꾸기가 없고, '게시판으로 옮기기' 고르기 모드는 기본 배치로 보여요. 픽셀 글꼴(갈무리, OFL)은 스킨을 쓸 때만 불러와요. 설정값은 `theme.skin` · `theme.shelf` · `theme.pview` 라서 Firestore 규칙 변경은 없어요
- **수정**: 삭제 후 재등록 없이 글 수정
- **가져오기**: NovelAI 이미지에서 프롬프트·설정 자동 읽기(읽은 뒤 이미지에서는 지워요), 텍스트 붙여넣기(SD 웹UI / NAI JSON), 이미지 여러 장 일괄 생성, JSON 백업 내보내기/복원
- **사람마다 다른 꾸미기**: 색상 프리셋·직접 지정, 글꼴 4종, 배치 4종, 모서리, 머리말, 프로필 사진. 남의 블로그/링크도 글쓴이의 디자인으로 보여요

## 배포 순서

### 1. Firebase 콘솔 (프로젝트 `code-94e7e`)

1. **Authentication → Sign-in method → 이메일/비밀번호** 사용 설정
   - 이메일 없이 가입하면 아이디가 `아이디@pbox.local`로 바뀌어 저장돼요(실제 메일 아님). 이메일을 적고 가입하면 그 이메일로 로그인하고, 로그인 창에는 '아이디 또는 이메일'을 입력해요
   - 재설정 메일 문구는 Authentication → Templates에서 바꿀 수 있어요. 메일이 스팸함으로 갈 수 있어요
2. **Firestore Database** 생성 (없다면)
3. **Firestore → 규칙**에 `firestore.rules` 내용을 붙여넣고 게시 (**아이디 바꾸기** 기능 때문에 규칙이 바뀌었어요. 이미 게시했다면 다시 게시해 주세요)
4. (권장) Google Cloud 콘솔에서 Firebase API 키에 **HTTP 리퍼러 제한**(`https://내아이디.github.io/*`)

### 2. GitHub Pages

저장소 루트에 파일을 올리고 **Settings → Pages → main / root** 선택.

### 3. 관리자 계정

사이트가 열리면 **가장 먼저 가입하는 계정이 관리자**가 돼요. 배포 직후 본인이 먼저 가입하세요. 이후 **설정 → 초대**에서 코드를 만들어 지인에게 링크를 보내면 돼요.

> 이전 버전 데이터(`meta/admin`, `handles` 등)가 남아 있으면 관리자 가입 대신 초대코드를 물어봐요. 새로 시작하려면 콘솔에서 `meta`, `handles`, `profiles`, `invites` 문서와 Authentication 사용자를 지워 주세요.

## 파일을 고쳐서 다시 올릴 때 (캐시)

브라우저가 예전 파일을 붙잡고 있으면 수정이 안 보여요. `index.html` 안의 `v=20261102w` 값(import map 전체 + `style.css` + `app.js`)을 **전부 새 값으로 바꿔서** 올리세요. 급할 땐 Ctrl+F5(강력 새로고침)도 돼요.

## 새 기능을 관리자에게만 먼저 켜기 (테스트용)

`config.js`의 `BETA_HANDLES`(지금은 `['wxyz']`)에 있는 아이디이거나 관리자 계정이면 `store.js`의 `isBeta()`가 `true`예요. 새 기능은 `if (isBeta()) { … }`로 감싸 올려서 먼저 확인하고, 괜찮으면 감싼 부분을 풀어 전체에 적용하세요. 화면에서만 가리는 방식이라 보안 장치는 아니에요(데이터 접근 제한은 `firestore.rules`로).

## 이전 버전에서 업데이트할 때

- **이번 업데이트는 전체 적용**이에요. `firestore.rules`를 다시 게시해야 해요(초대코드 생성이 관리자 전용으로 바뀌고, 이웃 배너 알림 규칙이 추가되고, **아이디 바꾸기** 규칙이 추가됨). 규칙을 게시하지 않으면 아이디 바꾸기가 '권한 없음'으로 실패해요. 회원이 예전에 만든 초대코드는 더 쓸 수 없어요.

- 예전 글(종류 없음)은 **그림체**로 표시돼요.
- 예전 방식(Firestore)에 저장된 이미지는 그대로 보이고, **그 글을 수정해서 저장하면 ImgBB로 옮겨져요.**

## 이미지(ImgBB)에 대해 꼭 알아두세요

- **ImgBB 이미지는 주소를 알면 누구나 볼 수 있어요.** 비공개/비밀번호 글의 이미지도 마찬가지예요. 다만 주소는 글 본문(비공개 글은 나만, 비밀번호 글은 암호화) 안에만 있어서 글을 못 열면 알 수 없어요. 절대 공개되면 안 되는 이미지는 올리지 마세요.
- **사이트에서 글을 지워도 ImgBB의 이미지는 남아요.** ImgBB API에 삭제 기능이 없어서, 지우려면 ImgBB 계정에서 직접 지워야 해요.
- API 키(`config.js`의 `IMGBB_KEY`)는 브라우저 코드에 들어가서 **누구나 볼 수 있어요.** 다른 사람이 그 키로 내 ImgBB 계정에 이미지를 올릴 수도 있으니, 남용이 보이면 ImgBB에서 키를 재발급하고 `config.js`를 바꿔 주세요.
- 이 사이트는 `i.ibb.co` 주소의 이미지만 화면에 표시해요(남의 글에 엉뚱한 주소가 있어도 안전하게).
- 올라가는 이미지는 WebP로 다시 인코딩돼요(긴 변 최대 3072px, 품질 93). 투명한 부분은 흰색으로 합쳐져요.

## 데이터 구조

| 컬렉션 | 내용 |
| --- | --- |
| `profiles/{uid}` | 아이디, 표시 이름, 소개, 테마(프로필 사진/배너는 ImgBB 주소) |
| `handles/{아이디}` | 아이디 → uid (중복 방지) |
| `posts/{id}` | 목록용 정보: 종류, 제목, 공개 범위, 태그, 발췌, 썸네일 |
| `bodies/{id}` | 본문: 공개·비공개는 평문, 비밀번호 글은 **암호문** |
| `invites/{코드}` | 초대코드 (사용 횟수) |
| `notifs/{내uid}/items/{가져간사람uid}` | 이웃 배너 알림 (시각, 읽음) |
| `users/{uid}/private/{postId}` | 내 비밀번호 글의 사본·키 (본인만 읽기 가능) |
| `images/{id}` | (예전 방식) Firestore 이미지. 새 글에는 쓰지 않아요 |

## 알아두면 좋은 점

- **비밀번호 글**: 서버에는 암호문만 올라가고 비밀번호는 저장되지 않아요. 잊으면 복구할 수 없지만 글쓴이 본인은 로그인하면 열 수 있어요. 암호문이 공개되어 있어 약한 비밀번호는 무차별 대입에 약하니 충분히 길게 정하세요.
- **링크 전용(목록 숨김)** 은 목록에서만 숨기는 기능이에요. 완전한 비공개가 필요하면 '비공개'나 '비밀번호'를 쓰세요.
- **이메일 없이 가입한 계정은 비밀번호를 복구할 수 없어요.** 이 경우 관리자가 Firebase 콘솔에서 사용자를 삭제하고 다시 가입시켜야 해요. 가입 후 설정에서 이메일을 등록해 두는 걸 권장해요.
- 블로그 목록은 한 번에 전부 읽고 화면에서 나눠 보여줘요. 글이 수백 개 이상이면 읽기 횟수가 늘어나요(무료 하루 5만 회).

## 문제 해결

- **"Missing or insufficient permissions"**: Firestore 규칙이 게시됐는지, 로그인 상태인지 확인하세요.
- **이미지 업로드 실패**: 메시지에 ImgBB 오류가 나와요. 키가 잘못됐거나(`Invalid API key`) 일시적인 네트워크 문제일 수 있어요. 저장을 다시 누르면 이미 올라간 이미지는 건너뛰고 이어서 올려요.
- **NovelAI 이미지에서 프롬프트를 못 읽어요**: 디스코드/메신저를 거쳐 재압축되었거나 Firefox 지문 방지 모드가 켜져 있으면 숨은 정보가 사라질 수 있어요. 원본 PNG를 쓰거나 텍스트로 붙여넣으세요.
- NovelAI가 이미지 메타데이터에 Effort를 기록하는지 확인하지 못해서, 이미지에서 가져올 때 **Effort는 자동으로 채워지지 않을 수 있어요.** 직접 골라 주세요.
