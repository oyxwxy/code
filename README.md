# 프롬프트 서랍

NovelAI 프롬프트를 **공개 / 비밀번호 / 비공개**로 백업하고, 링크로 공유하는 블로그형 사이트예요.
빌드 도구 없이 파일만 올리면 동작하는 순수 HTML + JS(ES Modules) + Firebase(Auth, Firestore) 구성입니다.

## 기능

- **공개 범위 3종**: 공개 · 비밀번호(브라우저에서 AES-GCM 암호화) · 비공개(나만)
- 공개/비밀번호 글은 **링크 공유**, "내 블로그 목록에 숨기기"로 링크 전용 글도 가능
- **초대 코드**: 관리자는 사용 횟수를 정해 여러 개, 일반 회원은 1회용 3개까지 → 지인도 자기 공간을 받아요
- **이미지 업로드**(자동 압축, 글당 12장, 대표 이미지·순서 변경), 라이트박스 보기
- **프롬프트 수정**(삭제 후 재등록 필요 없음), 캐릭터 프롬프트(V4), 네거티브, 생성 설정, 메모, 태그
- **가져오기**
  - NovelAI 이미지(PNG 메타데이터 / 알파채널 숨은 메타데이터)에서 프롬프트·설정 자동 읽기
  - 텍스트 붙여넣기(SD 웹UI 형식, NAI 코멘트 JSON)
  - NovelAI 이미지 여러 장 → 글 일괄 생성
  - JSON 백업 내보내기 / 복원
- **사람마다 다른 디자인**: 색상 프리셋·직접 색 지정, 글꼴 4종, 목록 배치 4종(리스트/그리드/갤러리/저널), 모서리, 머리말(가운데/왼쪽/배너), 프로필 사진
- 남의 블로그나 공유 링크를 열면 **글쓴이의 디자인**으로 보여요

## 배포 순서

### 1. Firebase 콘솔 (프로젝트 `code-94e7e`)

1. **Authentication → Sign-in method → 이메일/비밀번호** 사용 설정 (아이디를 `아이디@pbox.local` 형태로 바꿔 사용해요. 실제 메일은 안 보내요)
2. **Firestore Database** 생성 (없다면)
3. **Firestore → 규칙**에 `firestore.rules` 내용을 그대로 붙여넣고 게시 (기존에 쓰던 규칙과 동일해요)
4. (권장) Google Cloud 콘솔 → API 및 서비스 → 사용자 인증 정보에서 해당 API 키에 **HTTP 리퍼러 제한**(`https://내아이디.github.io/*`)을 걸어 주세요. 웹 API 키는 공개돼도 되지만 제한을 걸어두면 더 안전해요.

### 2. GitHub Pages

1. 이 폴더의 파일을 저장소 루트에 올리기
2. 저장소 **Settings → Pages → Branch: main / root** 선택
3. 발급된 주소로 접속

### 3. 관리자 계정 만들기 (중요)

사이트가 열리면 **가장 먼저 가입하는 계정이 관리자**가 돼요. 배포 직후 바로 본인이 가입하세요.
이후 **설정 → 초대**에서 코드를 만들어 지인에게 링크를 보내면 돼요.

> 이전 프로젝트에서 같은 Firebase를 쓰던 데이터(`meta/admin`, `handles` 등)가 남아 있으면 관리자 가입 화면이 안 나오고 초대코드를 요구해요. 새로 시작하려면 콘솔에서 `meta`, `handles`, `profiles`, `invites` 등 기존 문서와 Authentication 사용자를 지워 주세요.

## 데이터 구조

| 컬렉션 | 내용 |
| --- | --- |
| `profiles/{uid}` | 아이디, 표시 이름, 소개, 테마(색·글꼴·배치·프로필 사진/배너 이미지 ID) |
| `handles/{아이디}` | 아이디 → uid (중복 방지) |
| `posts/{id}` | 목록용 정보: 제목, 공개 범위, 태그, 발췌, 썸네일 |
| `bodies/{id}` | 본문: 공개·비공개는 평문, 비밀번호 글은 **암호문** |
| `images/{id}` | 이미지 data URL (한 장 950KB 미만으로 자동 압축) |
| `invites/{코드}` | 초대코드 (사용 횟수) |
| `users/{uid}/private/{postId}` | 내 비밀번호 글의 사본·키 (본인만 읽기 가능) |

## 알아두면 좋은 점

- **비밀번호 글**: 서버에는 암호문만 올라가요. 비밀번호는 저장되지 않아서 잊으면 복구할 수 없어요. 다만 글쓴이 본인은 계정에 저장된 사본으로 비밀번호 없이 열고 수정할 수 있어요. 비밀번호는 충분히 길게 정하세요(암호문이 공개되어 있어 약한 비밀번호는 무차별 대입에 약해요).
- **이미지는 암호화되지 않아요.** 이미지 ID는 추측 불가능한 난수라 링크/본문을 모르면 찾기 어렵지만, 이미지 자체를 암호화하진 않아요.
- **링크 전용(목록 숨김)** 은 목록에서 안 보이게만 하는 기능이에요. 완전한 비공개가 필요하면 '비공개'나 '비밀번호'를 쓰세요.
- **비밀번호 복구 기능이 없어요.** 이메일을 쓰지 않는 구조라서 분실 시 관리자가 Firebase 콘솔에서 사용자를 삭제하고 다시 가입시켜야 해요.
- 이미지는 Firestore에 저장돼서 **무료 용량(1GiB)** 안에서 쓰는 게 좋아요. Storage를 쓰지 않아 결제 수단 없이도 동작해요.
- 블로그 목록은 한 번에 전부 읽고 화면에서 나눠 보여줘요. 글이 수백 개 이상이면 읽기 횟수가 늘어나요(무료 하루 5만 회).

## 문제 해결

- **"Missing or insufficient permissions"**: Firestore 규칙이 게시됐는지, 로그인 상태인지 확인하세요.
- **남의 블로그가 안 열려요**: 브라우저 콘솔에 색인 생성 링크가 뜨면 눌러서 색인을 만들어 주세요(대체 쿼리가 필요한 드문 경우).
- **NovelAI 이미지에서 프롬프트를 못 읽어요**: 디스코드/메신저를 거쳐 재압축되었거나 Firefox의 지문 방지 모드가 켜져 있으면 숨은 메타데이터가 사라질 수 있어요. 원본 PNG를 쓰거나 텍스트로 붙여넣어 가져오세요.

## 파일 구성

```
index.html      진입점
style.css       디자인
app.js          라우터 · 상단바
config.js       Firebase 설정 · 상수
fb.js           Firebase 초기화
store.js        인증 · 데이터 계층
crypto.js       비밀번호 글 암호화
images.js       이미지 압축 · 저장
nai.js          NovelAI/SD 메타데이터 해석
theme.js        테마 계산
view-*.js       화면들
backup.js       백업 · 일괄 가져오기
firestore.rules Firestore 보안 규칙
```
